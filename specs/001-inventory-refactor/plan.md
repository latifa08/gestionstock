# Implementation Plan: Inventory System Core Enhancement & Refactor

**Branch**: `001-inventory-refactor` | **Date**: 2026-04-29 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-inventory-refactor/spec.md`

## Summary

Refactor the Memoir L3 inventory management system to enforce authentication on all API endpoints, add server-side input validation, fix transactional integrity for stock-affecting operations, implement soft-delete to preserve audit history, and add database-level constraints and foreign keys. The backend is Node.js/Express + PostgreSQL. No frontend changes in scope for this phase.

## Technical Context

**Language/Version**: JavaScript (Node.js 18+), React 19 (frontend — read-only this phase)
**Primary Dependencies**: Express 5, pg (node-postgres), bcrypt (existing), `jsonwebtoken` (new), `cookie-parser` (new), `joi` (new)
**Storage**: PostgreSQL 18.3 — database `stock`
**Testing**: Jest + @testing-library/react (existing); add integration tests for new middleware and transaction flows
**Target Platform**: Local development (Windows); web browser
**Project Type**: Web service (REST API) + React SPA frontend
**Performance Goals**: <100 concurrent users; single warehouse; no caching layer needed
**Constraints**: Must preserve all existing data; migrations must be reversible; frontend continues to work during transition (backward-compatible API changes only)
**Scale/Scope**: ~100 products, ~50 clients/suppliers; 11 database tables; ~1000 lines of server.js to refactor

## Implementation Phases

### Phase A: Database Migrations (no code changes, data-safe)

1. Run `001_add_archived_columns.sql` — adds nullable `archived_at` to 3 tables (zero impact on existing queries)
2. Run `002_add_fk_constraints.sql` — adds FK constraints (must run cleanup-orphans.sql first if any exist)
3. Run `003_add_audit_columns.sql` — adds `id_user`/`raison` to mouvements; `id_user`/`id_client` to ventes (nullable, backward compatible)
4. Run `004_add_db_constraints.sql` — adds CHECK constraints (will fail if existing data violates; verify first)
5. Run `005_create_refresh_tokens.sql` — creates new table

### Phase B: Auth Infrastructure

1. Install `jsonwebtoken`, `cookie-parser`, `joi` via npm
2. Create `Backend/middleware/auth.js` with `requireAuth(roles[])` factory
3. Create `Backend/middleware/validate.js` with `validateBody(schema)` factory
4. Create `Backend/routes/auth.routes.js` (login, register, refresh, logout)
5. Update server.js to use `cookie-parser` and mount auth routes

### Phase C: Route Extraction & Validation

Extract each endpoint group from server.js into its own routes file, adding:
- `requireAuth([...roles])` middleware
- `validateBody(schema)` middleware
- Fix: remove duplicate `/products` and `/clients` GET handlers

Order: product → client → fournisseur → mouvement → facture → vente → user → dashboard → rapport → stock-alert

### Phase D: Transaction & Integrity Fixes

1. Wrap `/api/vente` in a DB transaction; populate `ventes` and `vente_details` tables
2. Change DELETE handlers for produits/clients/fournisseurs to soft-delete (`archived_at = NOW()`)
3. Add `id_user` population to all mouvement INSERT calls (from `req.user.id`)
4. Fix rapport-stock endpoint to read from `produits.quantite` (not re-derive from movements)

### Phase E: Integration Tests

1. Write `tests/integration/auth.test.js` — login, refresh, expired token rejection, role rejection
2. Write `tests/integration/products.test.js` — CRUD with auth, soft-delete, FK constraint test
3. Write `tests/integration/vente.test.js` — atomic sale, rollback on insufficient stock, ventes table populated
